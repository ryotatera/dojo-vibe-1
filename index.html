【入力】
1. 誰のために作るか：（ここに1行目）
2. その人は何に困っているか：（ここに2行目）
3. 何があれば助かるか：（ここに3行目）

【ルール】
- 聞き返さない。足りないところは、もっともらしい仮説で埋める
- あなたが埋めた項目には、行頭に 🔮 を付ける
- 🔮 の項目には「その顧客に何と聞けば確かめられるか」を1行添える
- 断定しない（「〜と思われる」「〜の可能性が高い」で書く）

【埋める項目】
1. 今その人はどうやっているか
2. かかっている時間・費用（「1件◯分 × 月◯件」の形。数字が無ければ業種から仮に置く）
3. なぜ今まで誰も作らなかったのか
   （データが散っている／市場が小さい／量が多すぎる／判断が非定型／n=1すぎる から1つ選ぶ）
4. 誰が払うか（使う人と払う人が違う可能性を検討。その相手に予算を張る商習慣があるか）
5. どう届くか（「上の経路＝検索・広告・DM・SNS」か「下の経路＝紹介・口コミ・既存顧客・業界内」かを明示）
6. 受け取れるか（決済の禁止・要審査業種に当たるか。投資／医療／サプリ／法律相談／暗号資産／ギャンブル／アダルト／情報商材）
7. 競合と、DIY競合（顧客が自分でAIに作らせる場合）
8. 選ばれる理由（データ／責任／時間／埋め込み のどれかで書く。機能では書かない）
9. やらないこと（3つ）

【最後に】
確かめるべきことを、事業の成否を左右する順に3つだけ。
「確かめること → 誰に聞くか → そのまま使える質問文」の形で書く。
②どう届くか が仮説のままなら、量では取り返せないと明記する。

【制約】
- 画面は1つだけ。ルーティングを増やさない
- 操作は3つまで
- データは localStorage に保存（サーバー・DB・ログインなし。リロードしても消えない）
- ログイン・課金・メール送信は作らない
- 新しいライブラリを追加しない

【この見出しで書く】
1. このツールが解くこと（1行。「〜が分かる」「〜が減る」）
2. 使う人と、使う場面
3. 画面（上から順に何が出るか）
4. データ項目（項目／型／必須／例 の表）
5. 操作（3つまで。操作／何が起きるか の表）
6. やらないこと（3つ以上）
7. 完成条件（見れば誰でもYes/Noを判定できる形で3つ）
8. 保存方法（localStorage のキー名）

【書き方】
- 顧客仮説の「1件◯分 × 月◯件」から、データ項目と操作を直接起こす

          応用｜要件定義書があると、この先どう変わるか
          

            
要件定義書は「作るもの」を決める書類ですが、いちばんの効きどころは "作らないもの" を決めることです。

            
AIは頼めばいくらでも機能を足します。止める側の根拠が無いと、際限なく膨らんで、結局動かないものができます。
              「6. やらないこと」と「7. 完成条件」が、その歯止めになります。

            
実務でもそのまま使えます。外注するときはこれをそのまま渡せば見積もりが取れますし、
              顧客に見せるときは「7. 完成条件」を読み上げれば、認識のズレが着手前に潰せます。

            
そして、ここを作り直せば、何度でも作り直せます。気に入らなければ要件定義書を直して
              /build をもう一度打つ。コードを直すのではなく、設計図を直すのが速いです。

リポジトリrepository1つのプロジェクトを入れておく箱。パソコンのフォルダに近いものです。▸ STEP1で自分用のものを作ります

          
テンプレートtemplate中身が入ったひな型。Use this template を押すと、自分用のコピーが1つできます。▸ STEP1

          
Public / Private公開か非公開か。Publicは誰でも中身を見られます。パスワードやAPIキーは絶対に置かないでください。▸ STEP1でPublicを選びます

          
コミットcommit変更の保存。「ここまでの状態」に名前をつけて記録することです。▸ Claudeが自動でやってくれます

          
ブランチbranch作業用の枝分かれ。本番を壊さずに試せる場所です。▸ Claudeが自動で作ります

          
mainメイン本番のブランチ。ここに入った内容が、あなたのURLに公開されます。▸ STEP8でここに反映します

          
PR / プルリクエストpull request「この変更を本番に入れていいですか？」という提案書です。出しただけでは本番は変わりません。▸ STEP4・STEP8

          
差分diff変更前と変更後の違い。+42 -18 は「42行増えて18行減った」という意味です。▸ STEP4で中身を確認します

          
マージmergePRを承認して、本番（main）に取り込むこと。ここで初めてサイトが変わります。▸ STEP4・STEP8

          
READMEリードミー説明書。リポジトリを開いたとき、最初に表示される文章です。▸ テンプレートに入っています

          
.gitignore「これはGitで管理しない」という指定ファイル。パスワードを置く .env.local などを除外します。▸ 触らなくて大丈夫です

          
GitHub AppGitHubに機能を足す連携アプリ。今日つなぐClaudeがこれです。「認可（Authorized）」だけでは書き込めず、「インストール（Installed）」が必要です。▸ STEP3

          
プレビューデプロイpreviewPRを作ると自動で発行される確認用のURL。本番とは別なので、Mergeする前に動きを試せます。▸ STEP8

          
GitHub Pagesリポジトリの中身を、そのままWebサイトとして公開できる機能。▸ このページ自体がそれです

          
Forkフォーク他人のリポジトリを自分用に丸ごとコピーすること。今日は使いません（テンプレートを使います）。▸ 今日は使いません

          
Issueイシュー課題や要望を書き留めておくメモ機能。▸ 今日は使いません

バイブコーディングvibe codingコードを書くのをやめて、AIに指示して作ること。やることは「指示する」「見る」「OKを出す」の3つです。▸ 今日ずっとこれをやります

          
Claude Codeあなたの代わりに手を動かすAI。ブラウザ版は claude.ai/code で、クラウド上で作業します。パソコンには何も入りません。▸ STEP3でつなぎます

          
CLAUDE.mdクロードエムディーClaudeが毎回いちばん最初に読む指示書。「誰のため／解く課題／やらないこと／技術ルール」を書きます。今日いちばん大事なファイルです。▸ STEP5〜7で効いてきます

          
プロンプトpromptAIへの指示文のこと。▸ このページのコピーボタンで配っています

          
4つの型指示の書き方。①対象（どのファイル）②やること（1つだけ）③条件 ④禁止。この4つを埋めれば、だいたい通ります。▸ STEP4で覚えます

          
スラッシュコマンド/kickoff のように / で始める呼び出し。正体は .claude/commands/○○.md というただのテキストファイルで、中身は日本語の指示文です。自分で 増やせます。そのリポジトリにファイルが無ければ使えません。▸ STEP6の折りたたみで詳しく

          
仮説（🔮）まだ確かめていないこと。Claudeが埋めた項目には 🔮 が付きます。これがそのまま宿題になります。▸ STEP6以降

          
ハルシネーションhallucinationAIがもっともらしい嘘を作ること。実績や数字を勝手に書くことがあるので、公開前に必ず自分で確認してください。▸ STEP8の確認で効きます

          
コンテキストcontextAIが一度に読み込める情報の量。長い会話が続くと古い内容を忘れるので、1回の指示は1つに絞るのが確実です。▸ STEP8

          
デプロイdeploy作ったものをサーバーに載せて、世界から見える状態にすること。▸ STEP2で1回目をやります

          
ビルドbuild書いたコードを、ブラウザが読める形に変換する処理。ここで失敗すると公開されません。▸ Vercelが自動でやります

          
Vercelヴァーセル公開先のサービス。GitHubとつなぐと、マージするたび自動で公開し直してくれます。無料枠で足ります。▸ STEP2

          
Next.jsネクストジェイエスこのテンプレートが使っているWebサイトの土台。中身を知らなくても今日は困りません。▸ テンプレートに入っています

          
ローカル / 本番「ローカル」は自分の手元、「本番」は世界に公開されている方。今日は最初から本番だけを使います。▸ STEP2以降

          
環境変数.envAPIキーやパスワードなど、コードに書いてはいけない秘密の設定を入れる場所。第3回で扱います。▸ 今日は使いません

          
API / APIキー外部サービスを使うための窓口と、その合鍵。合鍵は絶対に公開リポジトリに置かないでください。▸ 今日は使いません
