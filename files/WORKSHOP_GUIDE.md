# 第1部：座学①②（前半60分）── 考え方

## 3. 今日の一行

> **作るのは安くなった。売るのは、むしろ高くなった。**

しかも、高くなった原因は「作るのが安くなったこと」そのものです。
誰でも作れる ＝ 誰でも売り込む ＝ 客の注意の奪い合いが激しくなる。
**客の1日は、今も24時間のまま。**

## 4. 事業の式 — AIが動かしたもの、動かさなかったもの

```
事業になるか ＝ （課題の深さ × 顧客数 × 払える金額）
               －（作るコスト ＋ 届けるコスト）
                      ↓              ↑
                1/10〜1/100に      むしろ
                   下がった        上がった
```

| 変数 | AIの影響 |
|---|---|
| **作るコスト** | 下げた。1/10 〜 1/100 |
| 課題の深さ × 顧客数 × 払える金額 | 一部を増やした。ただし「AIに関する需要」に限る |
| **届けるコスト** | **上げた。**しかも上げた原因は、作るコストが下がったこと |

**左側がゼロなら、右側をいくら削ってもゼロ。**

---

## 5. 機会は2方向から開いている

### ① 供給側の機会 ＝ ホワイトスペース

> 需要はあったが、開発費が需要を上回っていたので、誰も参入しなかった領域

「なぜ割に合わなかったのか」は5つに分類できます。**今日持ち帰る一番の道具です。**

| 型 | これまで割に合わなかった理由 | 今できる理由 |
|---|---|---|
| **A. データが散らばりすぎ** | 手で集めると人件費が売上を超える | クローラー＋構造化が自動 |
| **B. 市場が小さすぎ** | 1,000万円のシステムを買える規模の顧客がいない | 30万円で作れるので成立する |
| **C. 必要な量が多すぎ** | 2万ページを人間が書けない | 型 × データで生成できる |
| **D. 判断が非定型** | ルール化できず、人がやるしかなかった | LLMが読んで判断できる |
| **E. n=1すぎる** | 1人のために作る経済合理性がない | 自分で作れるので合理性が要らない |

> 自分の業界で「やった方がいいのは分かってるけど、金かけてまではやらない」と
> 放置されている作業は、たぶんA〜Eのどれかです。

### ② 需要側の機会 ＝ AI特有のニーズ

3年前には存在しなかった、**正真正銘の新しい需要**です。

| 型 | 中身 |
|---|---|
| **F. AIを使うための需要** | 導入支援・教育・ワークフロー設計（この講座がまさにこれ） |
| **G. AIを使ったことで生まれた需要** | 生成物の品質検証・情報漏洩の管理・社内ガバナンス |
| **H. AIに向けた需要** | AIに読ませるためのデータ整備・構造化 |

### 2種類には、決定的な非対称がある

| | ① 供給側（A〜E） | ② 需要側（F〜H） |
|---|---|---|
| 見つけやすさ | **見つけにくい**（現場を知らないと見えない） | **見つけやすい**（ニュースを読めば分かる） |
| 競合の数 | 少ない | **非常に多い** |
| 必要なもの | 業界の実地知識 | 速度と流通 |

> **見つけやすいということは、全員が見つけているということ。**

### 狙う順番

| | 狙う場所 | 理由 |
|---|---|---|
| **本命** | ① 自分の業界の、放置されてきた課題 | 見えている人が少ない |
| **次点** | **G / H** 自分の業界がAIを使い始めたことで生まれた課題 | 中にいる人にしか見えない |
| 条件付き | F 一般向けのAI導入支援・研修 | **先に流通を持っている場合のみ**成立 |

## 6. 届けるコストは「上がっている」

```
作るコストが下がる → 誰でも作れる・発信できる → 供給が10倍になる
→ でも客の1日は24時間のまま → 1件届ける費用が上がる
```

### ただし、上がったのは片方の経路だけ

| | 経路 | 状況 |
|---|---|---|
| **上** | 検索・広告・コールドDM・SNS | **獲得コストが上昇中** |
| **下** | 紹介・口コミ・既存顧客への追加提案・業界内の直接接触 | **変わらない** |

**AIが荒らしたのは上だけ。下は無傷です。**
だから今、**「すでに会える人がいること」の価値が跳ね上がりました。**

---

## 7. 立ち上げ方は、どう変わったか

### 同じ12ヶ月で、学習できる回数が30倍違う

```
従来型:  [調査2ヶ月][要件1][開発6ヶ月][検証3ヶ月]  → 学習 1回 / 年
AI時代:  [会う → 作る → 見せる → 捨てる] × 30回    → 学習 30回 / 年
```

能力の差ではありません。**試行回数の差**です。

### なぜ順番が変わるのか

```
AI以前:  調査コスト ＜ 試作コスト  → 調査で絞り込んでから作る
AI以後:  調査コスト ＞ 試作コスト  → 作って確かめる方が速くて正確
```

> 「あったら使いますか?」には全員が「使う」と答えます。情報がゼロです。
> でも動くものを見せて「使ってください」と言うと、**嘘がつけない。**

### 逆転した5つの前提

| 従来 | AI時代 |
|---|---|
| 作る前に確信を得る | **作って確信を得る** |
| 仕様を凍結してから開発 | **動かしながら仕様が決まる** |
| チームを作ってから始める | **1人で始めて、伸びてから増やす** |
| 資金調達 → 開発 → 売上 | **売上 →（必要なら）調達** |
| 外さないことが至上命題 | **速く外すことが至上命題** |

### だが、速くならなかったもの

```
昔:  作る 80%  /  会う 20%
今:  作る 20%  /  会う 80%
```

**やることが減ったのではありません。比率が入れ替わっただけです。**

### 新しく生まれた3つの罠

1. **進捗の錯覚** — 開発が遅かった時代は、その遅さが「本当にこれでいいのか」を考える時間を強制していた。AIはその摩擦を消した。**進捗と前進は違う**
2. **半分だけAI時代** — 作るところだけAI型にして売るところを放置すると、**在庫だけが10倍**になる
3. **調べて分かる機会は、もう埋まっている** — 競合もAIで調べている。残るのは**現場に入らないと分からない課題**だけ

## 10. 出口の3点確認 ← 今日の結論

**回った3つは全部これを先に押さえ、止まった2つは全部これで死にました。**

```
作る前に、3つだけ確認する（全部あわせて数日で終わる）

  ① 誰が払うか   … その相手は、この種のものに金を出す商習慣があるか
  ② どう届くか   … その市場が「実際に使っている」経路は何か
  ③ 受け取れるか … 決済・審査・規制が通るか
```

**①と②は、その業界の人に会わないと分かりません。③だけは規約を読めば分かります。**
この3つは、AIに聞いても分かりません。

> ③の要確認領域: 投資・金融／医療・健康／サプリ・美容の効能／法律相談／暗号資産／ギャンブル／アダルト／情報商材・副業

## STEP 4. ファーストプロンプト ── 指示には型がある

**4つ埋めれば、だいたい通ります。**

| | 何を | 例 |
|---|---|---|
| **① 対象** | どのファイルを触るのか | `app/page.tsx` のトップページを |
| **② やること** | 1回の指示に1つだけ | `docs/01_customer.md` の内容に合わせて書き換えて |
| **③ 条件** | 守ってほしいこと | 見出し1つ、説明3行、CTAボタン1つ |
| **④ 禁止** | やらないでほしいこと | 新しいライブラリは追加しない／色は既存の変数を使う |

> 新人に仕事を頼むときと同じです。違うのは、**やり直しがタダ**なことだけ。
> **「かっこよくして」では、何も決まりません。**

そのあとの流れ：

1. `+42 -18` のような**差分**が出る → クリックして中身を確認
2. 直したい行があれば、その行を選んでコメント
3. 納得したら **`Create PR`**
4. GitHubで **`Merge pull request`**
5. 2〜3分後、自分のURLをリロード

## 仕上げ ── 3回の往復で。追加 → 修正 → 削除 の順

一度に全部頼むと、何が効いたのか分からなくなります。**1回の指示で1つだけ動かします。**

| | | 例 |
|---|---|---|
| **①** | **追加** | 足りない要素を1つ入れる（料金の説明を1行） |
| **②** | **修正** | 文言と色を直す（見出しを◯◯に） |
| **③** | **削除** | 不要な部分を消す（使わないセクション） |

> **削除を最後にするのは、消してから足すと同じものをまた作らせることになるから。**
> 3回とも、それぞれPRを分けて出してください。まとめて出すと、どれが原因で崩れたか追えなくなります。

## よくある詰まり方 ── 非エンジニアが、必ず1回はやる5つ

| ✕ | 何が起きるか | → こうする |
|---|---|---|
| **一度に頼みすぎる** | 「トップと料金と問い合わせを作って」→ どこが失敗したか追えない | 1回1つに割る |
| **曖昧な言葉で頼む** | 「いい感じに」「モダンに」→ AIが勝手に決める | 色・文言・数を書く |
| **ライブラリを増やさせる** | 見覚えのない依存が増えて、あとで動かなくなる | 禁止条件に必ず入れる |
| **全部作り直させる** | 直したい箇所以外まで変わって、前の良さが消える | 差分で頼む |
| **確認せずMergeする** | 動かなくなってから、どこを戻せばいいか分からない | 3か所だけ見る |

> **全部やって構いません。**今日この場でやっておくほうが、1人でやって詰まるより安く済みます。

# 第4部：持ち帰るスターターキット

## 何が入っているか

```
.
├─ CLAUDE.md              ← Claude Code が毎回読む指示書（一番大事）
├─ app/
│  ├─ layout.tsx          ← 全ページ共通の枠。サイトのタイトル・説明
│  ├─ page.tsx            ← トップページの中身
│  └─ globals.css         ← 色・余白・文字サイズの定義
├─ docs/
│  ├─ 01_customer.md      ← 誰の何の課題か ＋ 出口の3点
│  └─ 02_onepager.md      ← 何を作るかの1枚仕様
└─ .claude/commands/      ← ショートカット
```

## CLAUDE.md の1章と2章を必ず埋めてください

| 章 | 中身 | 埋めないとどうなるか |
|---|---|---|
| **1章** 誰のためか | 顧客・困りごと・今どうしているか | Claudeが「それっぽいもの」を作る |
| **2章** 出口 | ① 誰が払うか ② どう届くか ③ 受け取れるか | **作れても事業にならない** |

2章が空のまま機能追加を頼むと、Claudeが**「先に出口を確認しませんか」と一度聞き返す**ようにしてあります。

## 使えるショートカット

| コマンド | 何が起きるか |
|---|---|
| `/customer` | 顧客と課題を1問ずつ聞かれ、`docs/01_customer.md` が埋まる |
| **`/gtm`** | **出口の3点を1問ずつ詰める。作る前に必ず通す** |
| `/plan` | 作る前に1枚仕様を作る。**まだコードは変えない** |
| `/build` | 1枚仕様にそって、小さく1ステップだけ実装する |
| `/check` | 公開前チェック（秘密情報・根拠のない数字・出口との整合・スマホ表示） |

## 注意

- リポジトリは **Public（公開）** です。**APIキー・パスワード・個人情報は絶対に書かないでください**
- AIのAPIを使う機能を足すときは、**必ず1回あたりのコストと上限**をセットで決めてください

# 第5部：宿題

### 1. 題材を1つ決める

条件は1つだけ：**その顧客を実名で3人挙げられること。**
アイデアの面白さで選ばない。**会える人がいるかで選ぶ。**

### 2. その3人のうち1人に、実際に15分だけ話を聞く

聞くのは **「今それをどうやっているか」だけ**。

- 解決策の話をしない
- 自分のアイデアを説明しない
- 「あったら使いますか?」と聞かない（全員「使う」と答えるので情報がゼロ）

### 3. 聞いた内容を `docs/01_customer.md` に書き、Claude Code に指示してサイトに反映する

> **宿題の本体は3ではなく2です。AIが代わりにやれない唯一の作業が、2番です。**

## 今日の板書まとめ

```
① 事業になるか ＝（課題の深さ × 顧客数 × 払える金額）－（作るコスト ＋ 届けるコスト）
                                                          ↓下がった   ↑上がった

② 機会は2方向
   ① 供給側 = 見つけにくい / 空いている / 現場を知らないと見えない
   ② 需要側 = 見つけやすい / 混んでいる / ニュースで分かる

③ AIが上げたもの   : 知らない人に届けるコスト（検索・広告・DM・SNS）
   AIが変えないもの : すでに会える人に届けるコスト（紹介・既存客・業界内）

④ 昔: 作る80% / 会う20%     →     今: 作る20% / 会う80%

⑤ 出口の3点確認 — ① 誰が払うか ② どう届くか ③ 受け取れるか

⑥ 「何が作れるか」は誰でも同じ答えになる。
   「誰に会えるか」だけが、全員違う答えになる。
```
